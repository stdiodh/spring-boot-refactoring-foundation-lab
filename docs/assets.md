# 리팩토링 기초 보강 제공 자산

## 미리 제공하는 것

- 기존 CRUD, 인증, 계정 복구 흐름
- 기존 테스트와 실행 환경
- layer-based 구조에서 feature-based 구조로 옮길 수 있는 출발 코드
- Validation, Exception Handling, 테스트 보강을 확인할 수 있는 기본 문서

## 왜 미리 제공하는가

- 이번 시퀀스의 핵심은 새 기능 개발이 아니라 동작 보존과 구조 개선입니다.
- 멘티가 전체 프로젝트를 다시 만들기보다 기존 코드를 읽고 책임을 나누는 데 집중하게 합니다.
- 테스트를 리팩토링 안전망으로 사용하는 흐름을 먼저 확인하게 합니다.

## 학생이 직접 작성하지 않는 범위

- 멀티모듈 전환
- DDD 전면 도입
- 대규모 성능 최적화
- 새로운 외부 인프라 도입
- 기능 요구사항 자체의 확장
